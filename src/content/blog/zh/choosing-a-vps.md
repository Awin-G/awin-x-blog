总有人问我怎么挑一台**自托管服务器**用的机器，而诚实的答案是：2026 年**选择 VPS**
并不比以前更难，只是更**难做好**。价格页上那些看着可以互换的方案，跑上半年之后表现
天差地别。这是我跑了一台公网机多年之后真正在用的清单：决定一套小方案是扎实还是脆弱的
那些 **VPS 配置**、那些毫无意义的营销数字，以及服务商永远不会写在页面上的问题。

## 小型自托管服务器真正该看的 VPS 配置

一台机器好不好用，取决于六件事，而其中一半并不是页面上字号最大的那个数字。

### 内存优先于 CPU，永远

对小方案来说，内存是你最先耗尽的东西。nginx、数据库、Git 服务、一两个容器、systemd
本身——它们全都想*常驻*。这就是不对称之处：CPU 是突发的，99% 的时间闲着，你只会注意到
那 1%；内存是平的，你要么装得下，要么就得 swap，而 swap 到网络磁盘上，正是一台「便宜」
机器悄悄死掉的地方。买内存，租 CPU。

- **极小：** 反向代理、静态站点、隧道端点。最小档位就真的够用，只要上面不住数据库。
- **小型：** Git、密码库、代理后面的几个服务。服务加上系统得装得下，还得给 page cache
  留地方——缓存正是机器「快」的原因。
- **宽裕：** 邮件、真正的数据库、几个租户。这里内存*就是*你买的东西，核心数几乎不重要。

### 磁盘类型与 IO

价格页上的「SSD」是一个类别，不是一项测量。真正要紧的是它属于**本地 NVMe**、本地 SATA
SSD，还是——那个坑——挂着 SSD 名号的网络存储。网络存储让便宜方案成为可能，也让数据库
像在思考人生。你会注意到的是 IOPS，而不是容量。如果服务商不肯说明磁盘类型，那本身就是
答案。

### 网络端口与带宽上限

有两个数字都叫「带宽」。**端口速率**（1 Gbps、10 Gbps）决定单次传输能冲多快；**每月
额度**决定你在被限速、被计费或被 nullroute 之前能搬多少数据。做博客或代理，额度更重要；
做大文件分发，端口更重要。

### IPv4 与 IPv6

IPv4 稀缺，服务商要真金白银去买，所以有些便宜档是**纯 IPv6**，配一个共享的、NAT 过的
v4 地址，甚至一个都没有。这对隧道或 CDN 后面的站点没问题；但对任何必须*接受* v4 入站
连接的东西是致命的——邮件、堡垒机、游戏服务器。而 IPv6 让你每个服务都拿到一个可路由
地址，防火墙规则会干净很多。确认服务商是真的**路由** IPv6，而不只是宣传它。

### 快照与备份

这俩不是一回事，而服务商最爱把它们混为一谈。**快照**是同一份存储、同一个账号下的时间点
副本：升级前回滚很好用，可一旦账号关闭或服务商消失就毫无意义。**备份**要能离开这栋楼。
快照工具免费就用，但请把异地那份当成真正的安全网。

### 位置与延迟

越近越好，但距离是最不重要的变量：peering、网络质量和司法管辖区更关键。选一个离你近
（自己 SSH 顺手）、并且在直接服务读者时离大多数人也近的区域。

## 那些会误导人的营销数字

- **核心数。** 共享主机上的「8 vCPU」是八个*切片*，切的是被争抢的物理核。邻居跑个
  构建就能吃掉你那份。一个老实的核胜过四个忙碌的核。
- **「不限量」带宽。** 没有什么是无限的，永远有一条合理使用条款。去读条款里的数字，
  别信按钮上的词。
- **突发内存（Burst RAM）。** 你并不*拥有*突发内存，只是在宿主机闲着时*借*一点——而那
  恰恰是你不需要它的时候。永远别按突发内存来定档。
- **「独享」CPU** 却没有分母。对着谁独享？去看 vCPU 与物理核的比例，或者干脆自己盯着
  steal time。
- **巨大的存储数字**却不带 IOPS。几 TB 的慢速网络存储，输给一小块快速的本地 NVMe。

## 便宜与高价服务商：钱到底花在哪

价格差很少出在 CPU 或磁盘上——那些都便宜。你付的钱花在三处：**网络与 peering**（更好的
线路、在负载下依然稳得住的低延迟）；**超售**（便宜方案塞进更多邻居，性能自然更不可预测）；
以及**支持与政策**（高价档几小时内回工单、封停前先通知，便宜档往往两样都做不到）。对
玩票的机器，只要我有真实的异地备份、并接受它可能提前一天通知就消失，我乐意用便宜档。
但对任何失败模式是*我被锁在外面*的东西——邮件、入口——我买的是网络和支持，不是核心。
我自己大多数机器都落在那个理智的中间档：一家靠谱、无聊、稍微贵一点的中端服务商。

## KVM 与 OpenVZ：虚拟化类型为什么重要

**KVM 与 OpenVZ** 这个问题，悄悄地决定了你能跑什么。**OpenVZ**——以及它的亲戚 LXC 和
Virtuozzo——是*容器*虚拟化：每个租户共享宿主内核。这很高效，所以方案便宜，但它限制你。
不能用自己的内核或内核模块。部分 `sysctl` 旋钮是锁死的，`iptables` 可能被宿主机部分接管，
嵌套跑 Docker 可能不稳甚至被禁。你是住在别人家里的一名租客。**KVM** 则是完全虚拟化：
你有自己的内核，于是 Docker、WireGuard、ZFS、自定义内核、自己的包过滤，全都行。它更贵，
通常也值这个价。

我的默认：除非有明确理由，否则选 **KVM**。邮件（你要完全掌控网络栈）和任何偏离普通
用户态的东西，我根本不会考虑容器方案。

## 什么时候一台小机器就够了，什么时候不够

大多数人买多了、用少了。小机器够用的信号很无聊：CPU 近乎空闲、内存大半是空的还带着
健康的 page cache、没用到 swap、出口流量离上限差得远。如果你是这样，就别为了一个仪表盘
去升级。真正说明你已经不够用的信号，同样具体：

- **正常运行时就在用 swap**，或者你得重启服务来腾内存。
- **steal time 很高**（`top` 里的 `st` 列）——你在替邻居的工作负载买单。
- **简单查询也 IO wait 很高**——瓶颈是磁盘，不是代码。
- **你老是撞出口限额**，或者 TLS 握手肉眼可见地慢。

一旦踩中其中一条，往上升*一*档，然后停在那里。为你还没有的流量预先买容量，是这行里
最常见的浪费；凌晨三点把自己的数据库 OOM 杀掉，是最常见的后悔。

## 端口 25、滥用政策，以及那些小字条款

这一节要在买之前就读，而不是等它咬你一口之后。

**端口 25。** 大多数服务商默认封掉出站 25 来挡垃圾邮件。如果你想*收*邮件，就需要入站 25
打开，而很多服务商不会开——或者只在企业档、等一段时间之后、或者得跟他们 argue。有些只
封出站，如果你走中继发信、自己收信，那没问题。请在迁移信箱*之前*确认政策。

**滥用政策。** 搞清楚收到 DMCA 或滥用投诉会发生什么。立刻、静默地封停，对任何你在意的
东西都是劝退项；一封警告邮件就不算。再查一下你打算跑的东西是否踩到可接受使用政策——
VPN 出口节点或 BT 客户端，在某些网络被禁，在另一些则没事。

**其余部分。** IP 是共享还是独享？多要一个 IPv4 收费吗？SSH 挂了能不能拿到控制台？
到这里，**选择 VPS** 已经不再关于配置，而是关于信任。

## 选择 VPS 的决策清单

付款之前，从上往下过一遍：

1. **定档：** 服务加上 page cache 能装下的最小机器是哪个？从「刚好装下」往上一档起步。
2. **内存与 swap：** 正常运行时不会 swap 吗？
3. **磁盘：** 本地 NVMe 还是 SATA SSD？IOPS 多少？是不是网络存储？
4. **网络：** 端口速率、每月出口额度、超额政策。
5. **IPv4/IPv6：** 我需不需要独享 IPv4？IPv6 是真路由的吗？
6. **快照：** 免费吗？而且无论怎样我都另有真实的异地备份吗？
7. **虚拟化：** KVM，还是一个我有理由接受的容器方案？
8. **端口 25 / 滥用：** 他们会解封邮件端口吗？怎么处理投诉？
9. **位置：** 离我和我的用户够近，司法管辖区我也能接受。
10. **支持：** 能快速联系到真人吗？政策有文档吗？

然后，验证你买到的东西，而不是相信那张页面：

```bash
# 在全新机器上先跑这些，再去信价格页。
nproc                              # 逻辑核；用 /proc/cpuinfo 确认真型号
free -h                            # 内存，以及是否已经在用 swap
lsblk -d -o NAME,SIZE,ROTA,MODEL   # ROTA=0 表示非旋转介质（SSD/NVMe）
dd if=/dev/zero of=./t bs=1M count=512 conv=fdatasync status=progress  # 粗测写入速度
ip -6 addr show                    # IPv6 是不是真的下发了？
vmstat 1 5                         # 盯 `st` 列：steal time 高 = 邻居吵闹
```

如果写入很慢、机器已经在 swap，或者 steal time 在往上爬，那么不管页面承诺了什么，
你都已经有答案了。

## 一句话规则

买内存和网络质量，别买核心数；选 KVM；留一份能离开这栋楼的备份；在爱上一个价格之前，
先读端口 25 和滥用政策。最好的**自托管服务器**，是那台你不再去想的、无聊的机器。
